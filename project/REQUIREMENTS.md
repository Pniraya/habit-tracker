# REQUIREMENTS.md

> Habit Tracker V1 产品需求基线。本文归纳已确认的产品范围与概念稿要求；未明确的行为标记为 TBD，必须在实现前确认。

## 1. 产品目标

开发一款轻量、离线、本地存储的 Android 习惯追踪应用。用户可以创建习惯、按计划记录每日进度、查看连续记录和统计，并为习惯设置多条每日提醒。

## 2. 平台与范围

- 目标平台：Android 15（API 35）；技术兼容基线见 `ARCHITECTURE.md`。
- V1 不需要桌面小组件。
- V1 不需要深色模式。
- 数据保存在本机；不提供账号、登录、云同步或服务端。
- 不运行常驻前台服务。
- 提醒精度：Normal；允许系统延迟，优先省电；不申请精确闹钟权限。

## 3. 习惯模型

### 3.1 追踪类型
- 布尔型：完成/未完成。
- 数值型：记录当天累计数值，并与目标值比较。
- 同一个习惯在 V1 创建后不允许直接切换追踪类型；历史语义变更需要单独设计迁移。

### 3.2 计划频率
- 每日。
- 工作日（周一至周五）。
- 自定义星期组合。

### 3.3 计划历史
- 计划变更应保留历史版本。
- 连续天数和统计按每个日期当时有效的计划计算。
- 非计划日不计入应执行次数，也不打断连续次数。

## 4. 核心页面与功能

### 4.1 今日页
- 显示今日完成数量，例如 `3/5`。分母只包含当日为计划执行日且未归档的习惯（ADR-010）。
- 显示温和、正向的鼓励文案。
- 显示习惯连续完成天数。
- 显示今日应执行的习惯卡片列表。
- 提供快速打卡入口。
- 提供底部导航。

### 4.2 统计页
- 支持周、月、年视图切换。
- 显示所选区间完成率。
- 显示最长连续天数。
- 显示月度日历热力图。
- 显示本周趋势。

### 4.3 习惯管理与详情
- 创建、编辑、归档习惯。
- 设置名称、图标、颜色、追踪类型、目标、单位、执行频率。
- 设置每日提醒，可添加多条提醒时间。
- 详情页显示当前连续、最长连续、本月次数、本周情况、近 5 周热力图、累计次数和完成率。V1 不提供“平均用时”（ADR-010）。

## 5. 视觉与交互

以用户提供的概念稿为视觉方向：
- 暖白：`#FAF7F2`
- 苔绿：`#5B8C6A`
- 杏橙：`#F2A65A`
- 雾蓝：`#8FAFC4`
- 炭灰：`#1C1B1A`
- 字体优先思源黑体 / HarmonyOS Sans；不可用时回退系统 sans-serif。
- 卡片圆角 20dp；主要按钮全圆。
- 打卡提供轻量触觉反馈与约 0.3 秒回弹。
- 全部完成时使用轻量叶片动画，不阻塞交互。
- 页面切换淡入并轻微上移约 12dp。
- 文案温和、具体，不制造连续打卡压力。
- 仅浅色主题。

## 6. 提醒需求

- 使用 Android 系统通知。
- 每个习惯允许多条每日提醒。
- 使用 Normal 非精确调度，允许延迟，不承诺准点。
- Android 13+ 请求通知运行时权限；拒绝权限时核心习惯记录功能仍可用。
- 完成当日目标后抑制当天后续提醒。
- 重启、时区/系统时间变化、提醒/计划变更、归档等情况需重建或取消提醒。
- 强制停止应用后的行为限制需在产品说明中明确。

## 7. 数据与隐私

- 核心数据本地持久化。
- V1 设计本地 JSON 导出/导入。
- 不上传习惯名称、日志、备份内容或设备标识。
- 导入前全量校验；导入写入具备事务性；冲突不得静默覆盖。

## 8. 统计与计算口径

- 连续天数按计划执行日计算，而不是自然日。
- 非计划日跳过。
- 过去已到期的计划日缺失或未完成，视为失败。
- 今天尚未结束时，未完成不提前判失败。
- 完成率分母仅包括统计区间内截至今天已到期的计划执行日。
- 分母为 0 时 UI 显示 `---`。
- 归档后保留历史数据；归档之后不再产生新的应执行次数。

## 9. 明确不属于 V1

- 桌面小组件。
- 深色模式。
- 账号、登录、云同步、服务端。
- 常驻前台服务。
- 精确闹钟权限与精确提醒承诺。
- 多模块 Gradle 架构（除非后续有批准的技术决策）。
