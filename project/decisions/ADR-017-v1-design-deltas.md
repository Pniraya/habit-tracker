# ADR-017: V1 设计偏差登记与归档层级语义

- 状态：`ACCEPTED`（2026-11-06 用户「其他你看着办」授权，偏差均已有任务记录）
- 日期：`2026-11-06`
- 决策人：AI 代行，依据用户 2026-11-06 的授权与既有 ADR-008/010
- 相关任务：`TASK-027`、`TASK-030`、`TASK-031`、`TASK-033`、`TASK-034`
- 关闭问题：外部评审 Q6（归档层级）、Q9（偏差记录方式）、Q10（统计周/年切换）

## Context
概念稿（`orgins/`）里有若干控件在当前数据模型下无法真实工作：提醒铃铛与时间、每次平均用时、图标/颜色编辑、减弱动效、统计周/年切换。另有一条用户原话「归档后的习惯存储结构为月份/日期的父子级」，当前实现是对 `archived_on` 的展示层分组。外部评审建议用**一份偏差 ADR + 一张追踪表**统一记录，避免评审把每个偏差当缺陷，或让偏差悄悄变成事实标准。

## Decision
1. **归档层级保持展示层树**：`archived_on` 仍是归档事实的单一来源，我的页按「年-月 → 日」派生分组；不建物理月/日父表。未来若建父子表，需要单独的 ADR 与迁移。
2. **`archived_on` 语义**：最近一次归档日期（归档 → 恢复 → 再归档会覆盖旧值）；归档期间不算「应做未做」，连续天数的计划判定沿用计划版本，归档日当天按 `ADR-005` 处理。
3. **提醒**：`F-012/013` 进入 MVP，排在备份之后；提醒数据模型 ADR 先于备份格式定稿。详情页暂不显示铃铛与时间。
4. **第三张统计卡**：保留「本月次数」，不恢复「每次平均」（依据 `ADR-010`，`duration_seconds` 仍为保留列）。
5. **编辑范围**：V1 只改名称/目标/单位，不改图标/颜色/类型（改类型会重解释历史日志）。
6. **统计周/年切换**：延后到 V1 之后；当前不可用的切换控件应隐藏而不是变淡。
7. **减弱动效**：读取 `Settings.Global.ANIMATOR_DURATION_SCALE` 列为 P3 小任务，不在本轮。
8. 需求文档写「应该」，任务文件写「现在」，本 ADR 写「为什么偏离」；逐项状态见 `project/DESIGN-DELTA.md`。

## Alternatives Considered
- 物理月/日父表：两个事实来源，归档/恢复要同时改两张表，日期边界不一致时数据会分叉；分组只是 `GROUP BY` 能得到的视图。
- 归档快照文件：归档习惯仍可恢复，快照会产生第二份副本并与恢复语义冲突。
- 为设计稿补时长数据：需要计时器/输入框 + schema v2 + 迁移 + 测试，成本与收益不成比例。

## Consequences
- 正面：偏差有唯一登记处，评审可当检查清单；数据模型不做无收益的复杂化。
- 成本：概念稿的若干控件在 V1 缺失，需要在交付说明里讲清。
- 影响文件：`project/DESIGN-DELTA.md`、`FEATURE_MATRIX.md` 脚注、`REQUIREMENTS.md`（仅状态标注，不改写需求原文）。
